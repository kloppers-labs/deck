# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What deck is

A Bubble Tea TUI "command center" with four tabs — **Files**, **Git**, **Run**, **HTTP** — over the current working directory. `main.go` loads config, maps `mouse` to program options (`hover` → all-motion, `click` → cell-motion, always `WithReportFocus`) and boots the root model in `internal/app`. After `p.Run()` returns, `main` calls `Model.StopAll` on the final model as a backstop so no task outlives deck. Everything else lives under `internal/`.

Deck does not call any AI API directly. The only AI feature is the Git tab's `ctrl+g` commit-message helper (`internal/aicommit`), which shells out to the user's already-authenticated `claude`, `codex`, or `crush` CLI (`mods` is a deprecated alias for `crush`). Editing is delegated to `micro` (configurable) via `tea.ExecProcess`, which suspends the TUI for the duration of the child process.

## Common commands

```bash
go build ./...                       # build
go test ./...                        # run all tests
go test ./internal/git -run TestX    # single test
go test -race ./...                  # race detector
go run .                             # launch the TUI
```

## Configuration (`internal/config`)

`config.Load() (Config, []Warning)` reads `$XDG_CONFIG_HOME/deck/config.toml` (falling back to `~/.config/deck/config.toml`), then a project-local `.deck.toml` found by walking up from the cwd to the directory holding `.git` (or the cwd itself). Later files override scalars and **append** `tasks`. The whole schema (spec §12) is defined up front — `Files`, `Viewer`, `LSP{Enabled, Prestart, RequestTimeoutMS, Servers}`, `Git{ConfirmCommit}`, `Task{Name, Cmd, Dir, Env, Kind}`, plus `mouse`, `editor_return`, `micro_bundle`, `micro_lsp` — so later work only reads config, it never adds fields.

- Defaults live only in `Default()`. Files are decoded on top of it, so omitted booleans keep their defaults and an explicit `false` sticks; afterwards zero strings/numbers and nil slices/maps are filled from `Default()`.
- Nothing is fatal: a decode error, an unknown key (with a "did you mean" suggestion from the schema) or an invalid enum value (`mouse`, `editor_return`, `micro_lsp`, `files.icons`) becomes a `Warning`. `main` passes the warnings to `app.New(cfg, warnings)`, and `Init` shows them as one toast.
- `lsp.servers` is empty by default; built-in server definitions belong to the lsp package. `LSPServer.Enabled` is a `*bool` so an omitted `enabled` means on.
- Configured `tasks` are always shown; tasks detected by the Run pane are merged after them (see `internal/runner`).

## Architecture

### Root model owns the chrome (`internal/app`)

`Model` holds one value of each pane type and an `active tab`, plus the toast queue, help-modal state and mouse state. `app.go` is the model and routing, `mouse.go` the mouse translation, `help.go` the help modal.

**Routing contract (`ui.Routed`).** Every async or cross-tab message implements `RouteTo() ui.Dest` (`DestApp`, `DestFiles`, `DestGit`, `DestRun`, `DestHTTP`). `app.Update` delivers any `ui.Routed` message to its destination whichever tab is active — today the Git pane's async results (`git.RefreshMsg`, `StatusLoadedMsg`, `DiffLoadedMsg`, `CommitMsgReady` and its internal op/commit/branch/log results), `runner.OutputMsg`/`ExitMsg`/`DetectedMsg`, `httpc.RespMsg`/`LoadRequestMsg`, the viewer's `DocLoadedMsg`/`DocHighlightedMsg`/`MarkdownRenderedMsg` and `files.ReloadMsg`/`RevealMsg`/`InvalidateMsg` (→ Files), and the app-bound `ui.ToastMsg` and `ui.FocusTabMsg` (switch to the tab owning a `Dest`). A message that also implements `ui.Broadcast` (`AlsoTo() []Dest`) is delivered to those destinations too: `git.StatusLoadedMsg` reaches Files as well, for the tree's git badges. A new async message needs only a `RouteTo` method, never a new `case` in `app.Update`. Other app-level cases: `editor.OpenMsg{Target}` (from the viewer, the Git tab's `e` and a Run problem's `enter`; `editor.Open(t)` builds the command) is handled in `internal/app/editor.go`: `editor.Launch(cfg.Editor, target, opts)` returns the command and a `Mode` — `Suspend` runs it through `tea.ExecProcess`, `Detach` (VS Code family without `-w`, zed/subl, JetBrains) starts it in the background with an `opened in …` toast (both cases are matched before the `ui.Routed` case); `git.GenCommitMsgRequest` runs `aicommit.Generate` on `Repo.StagedDiff` (90 s timeout, cancellable through `Ctx`); `editorClosedMsg` carries the bridge state read by the exec callback (`editor.ReadState`, then the temp file is removed) and returns `git.Refresh`, `files.RevealMsg` at `editor.ReturnTarget` (`editor_return = "follow"` goes where micro ended if it is under the cwd, `"origin"` back to where deck launched it; `files.ReloadCurrent` when there is no target), `files.InvalidateMsg{Saved}` for files saved in micro, and an error toast if the editor failed; `editor.SyncedMsg` (from the startup sync) becomes one warning toast when `Notify` is set; `WindowSizeMsg` also returns `files.ResizeCmd()` so rendered markdown re-wraps; `spinner.TickMsg` fans out to every pane with a spinner. `Init` sends `files.Init`, the first `git.Refresh`, `run.Init` (background task detection) and, when `micro_bundle` is on and the editor is micro, `editor.SyncCmd` (micro runtime sync), so the status bar's branch and the repo-root project name arrive asynchronously. Keys, mouse events and everything else go to the active pane after global handling.

**Frame contract.** `SetSize(w, h)` is a pane's **outer** box, borders included, and `View()` must return exactly `h` rows of at most `w` columns — panes end `View` with `ui.Fit`. The body is `h - 5` (tab bar 3, status 1, footer 1) and `app.View` fits every section again as a backstop. Below 60×16 the frame is a centred `terminal too small` notice. `layout_test.go` checks every tab (with and without help) at 60×16, 80×24, 120×40 and 200×50 using long-name fixtures.

**Capture rules.** A pane's `Capturing()` is true only while text is being typed or a modal is open (filter, commit box, viewer `/`/`:` prompt or pending chord, HTTP insert mode or `.http` sidebar, Run task filter or log search, branch picker, a y/n prompt); reading, scrolling and selecting never capture. While capturing, single-letter globals (`q`, `?`, `1`–`4`) are suppressed and the footer shows `esc normal` instead of `q`/`?`. Capture-proof keys are checked first: `ctrl+c`, `tab`/`shift+tab`, `alt+1`…`alt+4`, `F1`, `alt+m`.

**Mouse.** `app.mouse` drops motion events on the same cell as the last one, handles tab-bar clicks with the pure `tabHitTest`, ignores the status and footer rows, and forwards body events to the active pane with `Y` reduced by the tab-bar height; containers keep translating into child-local coordinates (`ui.Rect.Local`). `alt+m` toggles reporting at runtime (`tea.DisableMouse` / re-enable per `cfg.Mouse`) and the footer shows `mouse off`. `ui.ClickTracker` turns presses into click counts (double-click = same cell within 400 ms).

**Toasts and status bar.** `ui.ToastMsg{Level, Text, TTL}` (or `ui.Toast(level, text)`) from anywhere shows on the right of the status bar; the newest live toast wins and each expires through a `tea.Tick`. The pure `statusLine(left, right, w)` lays out project · branch · dirty · running on the left and the toast on the right, truncating the left side first.

**Quit and re-run (`quit.go`).** `q`/`ctrl+c` quit at once when no task runs; otherwise a modal asks `N tasks running (a, b): quit and stop them? [y/N]`. `y` runs `run.StopAllCmd` (signal now, wait up to 5 s off the UI goroutine, then `tea.QuitMsg`), any other key dismisses it, and a second `ctrl+c` force-quits (main's backstop still stops the tasks). `ctrl+r` (gated by capture) re-runs the last Run task from any tab without switching. The Run tab badge shows the running count and a red `✗N` for failed tasks.

**Help.** `?`/`F1` opens a centred modal composited with `ui.Overlay` over the dimmed body (`ui.Dimmed`), grouped Global / active tab / Mouse and built from the same `key.Binding` values the panes export. It is modal (only `ctrl+c` escapes it), scrolls with `j`/`k`/wheel, filters with `/`, and closes with `esc`/`?`/`F1`/`q`.

When adding a new tab: add to the `tab` enum, `tabNames`, `tabDests`, the `Model` struct, `New`, `resize`, `capturing`, `routeTo`, `paneView`, `paneBindings`, the `globalKey` switches and `ui.Keys` (`N` and `alt+N`), plus a `ui.Dest` for it.

### Each pane is its own package

Panes are value types (so the root model can copy them in/out of `Update` cheaply). Each exports `New…`, `SetSize`, `Update(msg) (Self, tea.Cmd)`, `View`, and usually a `Capturing() bool`.

- `internal/files` — the Files tab container: a directory listing on the left and a `viewer.Model` in a bordered box on the right. `New(dir, cfg)` lists only the directory; `Init` loads the selected file. Moving the selection calls `viewer.Open` (async), and the pane remembers the selected entry per directory and the viewer `Spot` per file, so going up a directory selects the child you came from and returning to a file restores its position. Focus is list or viewer: `enter`/`l`/→ on a file focuses the viewer (on a directory enters it), `h`/←/`-` goes up, `e` opens the editor at line 1, `x` on a `.http` file emits `httpc.LoadRequestMsg`, and in the viewer `esc` first closes the viewer's prompt/search and then returns to the list (in the list it clears an applied filter). Symlinked directories count as directories. Mouse is routed by region: list wheel/click/double-click as before (`ListTop` is the first row's local Y), and events right of the list are translated into viewer-local coordinates (`viewerRect`). `ReloadMsg` (from `ReloadCurrent`) re-lists and reopens the file in place; `RevealMsg{Target}` selects a file (changing directory if needed) and opens it at the target position. `SelectedPath()`/`ViewerLoc()` are the cross-package accessors.
- `internal/viewer` — the read-only code viewer. `Load`/`LoadCmd` stat, read the whole file (`io.ReadAll` over a 20 MB `LimitReader`, so no short reads; larger files are `Truncated` with a header banner), detect binaries and split into `Raw` (`\r` stripped; editor/LSP columns), `Plain` (tabs expanded, control bytes → U+FFFD one-for-one) and `Styled` (filled later). A 16-entry LRU `Cache` keyed by path+mtime+size+theme+tab width is shared by all copies of the model. Highlighting runs as a command after the plain text is shown: the whole file is tokenised once (multi-line comments stay correct) and token types map to cached SGR prefixes per (theme, colour profile; truecolour only when `COLORTERM` says so); files over `viewer.max_highlight_bytes` or 50k lines are highlighted in 2000-line chunks around the viewport, and lines over 4000 columns stay plain. `lexmap.go` maps .NET extensions (`.csproj`/`.props`/`.targets`/`.resx`/`.xaml`/`.slnx` → XML, `.razor`/`.cshtml` → HTML, `.sln`/`.editorconfig` → INI) before chroma's own matching. Every request carries a `gen` from a shared atomic counter; stale loads are dropped and superseded highlights skip their work. Markdown renders through glamour by default (renderer cached per style and width, mermaid output cached per block) and `m` toggles the raw source. `View` is O(visible rows): `relayout` computes the rows in `Update`, each row is cut with `ansi.Cut` and only rows with a cursor or search hit go through the pure `Paint(styled, spans)`. Pure helpers, each table-tested: `geometry.go` (`DispCol`/`RuneCol`, `ScreenToDoc`/`DocToScreen` with gutter, offset and wrap, `EnsureVisible` with 3-row/8-column scroll-off), `words.go`, `search.go` (smart-case, literal or regex, wrap-around), `chord.go` (`g`/`z`/`]`/`[` prefixes, no timers), `history.go` (jump list for M7), `spans.go`. Keys follow spec §8.3 (no digit counts — `1`–`4` stay tab keys); `e` emits `editor.OpenMsg` at the cursor's line, column and top; `y`/`Y` copy over OSC52 (`clipboardOut` is the test seam). `Capturing()` is true only while the `/` or `:` prompt is open or a chord is pending. The wheel scrolls `viewer.scroll_lines`, ramping to 3× for events under 40 ms apart (the clock is injectable); shift+wheel scrolls horizontally; a click places the cursor. `BenchmarkViewerView` (200 rows over 50k lines) runs in well under 1 ms.
- `internal/editor` — launching editors and deck's bundled micro runtime (spec §7). `Target{Path, Line, Col, Top}` (1-based, 0 = unset) and `OpenMsg{Target}` (→ app).
  - `profiles.go`: `Args(editor, target)` is the pure per-editor table (micro/emacs/kak `+L:C`, vim/nvim `+call cursor(L,C)`, hx/zed/subl `file:L:C`, code family `-g file:L:C`, nano `+L,C`, JetBrains `--line L --column C`, `{file}`/`{line}`/`{col}` templates, unknown → path only; `Line == 0` → no position). `Launch` wraps it into an `*exec.Cmd`.
  - `micro.go`/`root.go`: for micro, `cmd.Dir = ProjectRoot(path, cwd)` (solution, then go.mod/tsconfig/package.json, then `.git`, never above the cwd — mlsp takes `rootUri` from it), `MICRO_CONFIG_HOME=~/.config/deck/micro` and `-colorscheme dracula` when the bundle is on, `MICRO_TRUECOLOR=1` only for `COLORTERM=truecolor|24bit`, `DECK_EDITOR_STATE`/`DECK_EDITOR_TOP` for the bridge.
  - `assets.go`/`merge.go`/`servers.go`/`bundle.go`: the runtime is embedded from `runtime/` (never a directory named `micro`). `RunSync` (an `Init` cmd) probes `micro -version`, renders `plug/mlsp/z_deck.lua` from `lsp` specs + `[lsp.servers]` (absolute paths of installed servers, autostart, diagnostics, a `handleRequest` wrap answering `workspace/configuration`, `client/registerCapability`, `window/workDoneProgress/create`), and `Sync` writes files only when their sha256 in `.deck-manifest.json` changed, removes only files it wrote earlier, skips MicroOmni below micro 2.0.14 or without fzf/rg/bat, skips mlsp when `micro_lsp = "off"`, and merges `settings.json`/`bindings.json` adding missing keys only (files with comments are left alone). Third-party plugins are pinned by `scripts/vendor-micro-plugins.sh` (see `THIRD_PARTY_NOTICES.md`).
  - `plug/deck/deck.lua` + `state.go`: the bridge restores the top line on the first event (the view has no height at `postinit`), snapshots path/line/col/top on every event (written only on change, plus `preQuit`/`preQuitAll`), records saved files, and binds `Alt-MouseLeft` to go-to-definition. `ReadState` ignores missing/stale/malformed files.
  - `doctor.go`: `Check` lists problems (micro missing or older than 2.0.14, missing fzf/rg/bat, missing language servers); `NotifyOnce` shows them once per manifest digest and issue set.
  - `smoke_test.go` (build tag `microsmoke`) drives real micro in a pty: `go test -tags microsmoke ./internal/editor -run Smoke`.
- `internal/git` — the Git tab and the git CLI layer. `exec.go`'s `runGit(ctx, dir, args...)` keeps stdout and stderr apart (so CRLF warnings never reach a diff), forces `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `LC_ALL=C`, and applies a 10 s timeout unless the context already has a deadline (remote ops use 120 s). `OpenRepo(ctx, cwd)` resolves `Repo{Top, GitDir}` once; every `Repo` method runs as `git -C Top` with root-relative paths, so launching from a subdirectory works. `Repo.StatusSnapshot(ctx, includeIgnored)` parses `status --porcelain=v2 --branch -z` with the pure `ParseStatusV2` into `Snapshot{Branch, Upstream, Ahead, Behind, Initial, Entries}`; `Items` groups entries into Staged / Unstaged / Untracked / Conflicts sections (an `MM` file is in both Staged and Unstaged, each with its own diff; untracked files diff with `--no-index` against `/dev/null`).
  - The pane (`pane.go`, `diff.go`, `commit.go`, `branches.go`, `loglist.go`, `view.go`) never calls git synchronously: `NewPane(Options{Theme, CommitAI, ConfirmCommit, Dir})` runs nothing, `RefreshMsg` returns a load command producing `StatusLoadedMsg{Seq}` (stale seqs are dropped and the last state stays visible behind a spinner), cursor moves debounce the diff load by 50 ms (`diffDueMsg`), and diffs are cached per path, section, index mtime and work-tree file stamp, capped at 200 KB with a `… N more lines · e open` footer. After a reload the cursor stays on the same entry, or on its neighbour in the same section when the entry moved.
  - Focus is explicit: in the list `j`/`k` only move the cursor; `enter`/`→`/a click on the right focuses the diff, where `j`/`k`/`ctrl+d/u`/`g`/`G` scroll and `esc`/`h` return. `space` stages or unstages per section, `a`/`A` stage/unstage all, `X` discards after a y/n prompt, `e` emits `editor.OpenMsg` at `firstHunkLine` of the shown diff, `f`/`p`/`P` fetch `--prune` / pull `--ff-only` / push (setting the upstream when there is none) as one busy op at a time, `b` opens the branch picker (cursor on the current branch, `n` new via `switch -c`, `D` delete with a prompt, `enter` uses `switch`), `l` swaps the list for a `bubbles/list` log of 200 commits (`enter` shows `show --stat -p`).
  - The commit box is a `bubbles/textarea` (subject counter turns red past 72): `ctrl+s` commits (through the huh confirm when `git.confirm_commit`), `alt+a` toggles amend and prefills the last message, `ctrl+g` asks for an AI message — the box shows a spinner, `esc` cancels, a failure keeps the typed text, reports it in the status line and raises an error toast. Commits are async and pass the message on stdin. `Branch()` (with `↑a ↓b`), `DirtyCount()` and `Top()` feed the status bar.
- `internal/aicommit` — no UI. `BuildArgs` maps a backend to its CLI invocation; `Generate(ctx, backend, model, diff)` pipes the diff (capped at 60 KB on a line boundary) to the CLI on **stdin**, never argv, captures stderr into the error, and strips Markdown fences; `Available` checks `PATH`. Tests swap the package-level `execCommand`/`lookPath` seams for a helper process.
- `internal/runner` — Run tab.
  - `procgroup.go`: each task runs under `sh -c` in its own process group (`Setpgid`), in `Task.Dir` (relative to the root) with `Task.Env` plus `FORCE_COLOR`/`CLICOLOR_FORCE`/`DOTNET_SYSTEM_CONSOLE_ALLOW_ANSI_COLOR_REDIRECTION`. Stopping cancels the context: `cmd.Cancel` sends SIGTERM to the group, a reaper sends SIGKILL to whatever is left after `killDelay` (3 s), and `proc.done` closes only once the group is gone. Output is split on `\n`, `\r\n` and bare `\r` into `chunk`s; a reader that would block drops lines once stopped so a stop never deadlocks.
  - `logbuf.go`: capped line buffer with stable absolute line numbers; a `\r`-terminated chunk is overwritten by the next one. `logview.go`: per-task scroll/follow (`↓ N new`), smart-case search, wrap, and problems; it renders only the visible rows.
  - `problems.go`: pure matchers for msbuild/dotnet and tsc (`path(l,c): error CODE: msg`), tsc `--pretty` and Go (`file.go:l:c:`). Paths resolve against the task dir; `enter` on a problem emits `editor.OpenMsg`.
  - `runner.go`/`dotnet.go`: `Init` detects tasks in the background (`DetectedMsg`): Go, npm/pnpm/yarn/bun scripts (from the lockfile), Angular, .NET (walks 3 levels skipping `bin`/`obj`/`node_modules`/`.git`; build/test the root `.sln`/`.slnx`, run/watch each Web or Exe project), Python, Cargo, Gemfile, Makefile/justfile. Capped sources report `+N more`. Detected tasks whose name or command is already configured are dropped; the rest show as `auto`.
  - `pane.go`: list ↔ log focus (`l`/click into the log, `esc`/`h` back), `StopAll(timeout)`/`StopAllCmd`, `Rerun`, `RunningNames`, `FailedCount`; a failed exit raises an error toast and the header shows `exit N`.
- `internal/httpc` — REST client. `httpc.go` holds pure helpers: `buildRequest` (loopback hosts default to `http://`, a JSON body gets an auto `Content-Type` shown greyed), header parsing/formatting and Chroma highlighting. `pane.go` has normal mode (not capturing: `j`/`k`/`g`/`G`/wheel scroll the response, `[`/`]` Body/Headers, `i`/`enter`/click to edit) and insert mode (`esc` back); `ctrl+s` sends, `esc` cancels an in-flight request (requests carry a `seq`, so a late reply is ignored), latency includes reading the body, and bodies over 1 MiB show `truncated at 1 MiB`. `httpfile.go` parses `.http` files (`###`, `# @name`, `@var = value`, `{{var}}`, `{{$guid}}`, `{{$timestamp}}`, `{{$dotenv KEY}}`, `{{$processEnv KEY}}`); variables resolve at send time, file variables over the environment. `env.go` loads the nearest `http-client.env.json` (+ `.private`, `$shared`); `ctrl+e` cycles environments. `sidebar.go`: `ctrl+o` lists requests from `**/*.http` (depth 4, 100 files), and `LoadRequestMsg` loads a request and focuses the tab.
- `internal/ui` — shared lipgloss styles and the global keymap (`keys.go`), plus the chrome primitives: `route.go` (`Dest`, `Routed`, `Broadcast`), `focus.go` (`FocusTabMsg`), `fit.go` (`Fit`, `FitWidth`), `overlay.go` (ANSI-safe `Overlay`, `Dimmed`), `toast.go` (`ToastMsg`, `Toast`), `rect.go` (`Rect`), `click.go` (`ClickTracker`). All width math goes through `charmbracelet/x/ansi`, so escape sequences are never split.
- `internal/config` — see Configuration above.
- `internal/lsp` — in-house LSP client, standard library only (no Bubble Tea, no other `deck/internal` import; `TestImportsStandardLibraryOnly` enforces it). `conn.go` is JSON-RPC with Content-Length framing; `registry.go` holds `DefaultSpecs()` (csharp-ls, gopls, typescript-language-server), `MergeSpecs` for config overrides, `FindRoot` (markers in priority order, walking up to the git top level / `$HOME`, never `/`) and `LookupBinary` (`PATH`, then `~/.dotnet/tools`, `~/go/bin`, `$GOPATH/bin`, Homebrew). `Manager.ClientFor(ctx, path)` lazily starts one `Client` per (server, root), and routes virtual URIs (csharp-ls `csharp:/…` metadata, read through `Client.Metadata`) to an already-running client; `Prestart(ctx, cwd)` eagerly starts only servers with `PrestartMarkers` (csharp-ls when a `.sln`/`.slnx` is found). A missing binary fails once and is never retried; a crashed server restarts once. Clients track Starting → Indexing → Ready from `$/progress` (or 2 s without progress), keep a 30-document didOpen LRU, and resync on mtime change or `Reload`. `Events()` carries `StatusEvent`/`DiagnosticsEvent`/`LogEvent`/`ShowMessageEvent` through a 256-entry queue that drops logs first. `Shutdown(ctx)` sends shutdown/exit, then kills the process group (servers start with `Setpgid`). Columns stay in the server's negotiated encoding; convert with `RuneToUnits`/`UnitsToRune`/`ByteToUnits`/`UnitsToByte`. Tests drive `lsptest`, an in-process fake server over `net.Pipe`, through the injectable `Starter`; `integration_test.go` runs real gopls when installed.

### Streaming pattern (used by `runner`)

The process goroutine pushes `chunk`s onto a buffered channel and the exit onto a second one. `proc.next()` returns a `tea.Cmd` that blocks for the first chunk, then drains up to 256 lines or 16 ms into one `OutputMsg`; once the line channel closes it returns the `ExitMsg`, then nil. After each `OutputMsg` the pane returns `proc.next()` again, so Bubble Tea keeps a single read pending.

### Testing notes

Tests sit next to the code they cover. Panes are driven by calling `Update` with `tea.KeyMsg`/`tea.MouseMsg` and running returned commands synchronously; never a `tea.Program`. Cross-package checks use small exported accessors (`git.Pane.Reloads`, `files.Model.SelectedPath`/`ViewerLoc`) because `export_test.go` seams are invisible to other packages. The invariant tests are `TestFrameFitsTerminal` (`internal/app/layout_test.go`) and `TestAsyncRoutedWhileOtherTabActive` / `TestRunnerOutputRoutedWhileOtherTabActive` (`internal/app/app_test.go`, the latter runs a real `sh` task). The `aicommit`, `httpc`, `git` and `config` packages have substantial unit coverage of their pure helpers. `internal/git/integration_test.go` exercises the real `git` CLI against temp repos (isolated from the user's global config) — needs `git` on `PATH`; git pane tests drive real repos through a `settle` helper that runs returned commands and feeds routed results back, and `TestNewPaneRunsNoGit` counts `runGit` calls through the `execCount` seam. Run `go test -race ./internal/lsp/...` after touching `internal/lsp`, `go test -race ./internal/viewer/ ./internal/files/` after touching the viewer, and `go test -race ./internal/runner` after touching the runner; its process tests run real `sh`/`sleep` pipelines with unique `sleep 30.NNNNNN` markers and check `pgrep` afterwards. `go test -bench ViewerView ./internal/viewer/` guards render cost.
